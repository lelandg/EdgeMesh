# Global Agent Configuration Merge Audit

**Date:** 2026-08-12

**Prepared by:** Codex
**Scope:** Audit of the native Windows Codex and Claude Code user configuration after a WSL-originated `agent-config-merge-skill` import. Inspection was read-only except for one approval-state side effect disclosed below.

## Executive summary

The Codex side is structurally sound: `C:\Users\aboog\.codex\config.toml` parses as TOML, the inspected JSON files parse, the Windows executables and directories referenced by the active Codex runtime configuration exist, and the bundled CLI reports `codex-cli 0.147.0-alpha.6.6`. The merge did not produce a generally corrupt Codex configuration.

There are, however, two high-priority functional defects and several cleanup items:

1. Claude Code's global model value is almost certainly merge-corrupted: `claude-fable-5[1m]` contains what looks like a copied ANSI fragment and is not a documented model alias or model name.
2. The three imported Claude MCP definitions are in an inert user-level location, omit their executable commands, and are not configured in either Claude's actual user MCP store or Codex's MCP configuration.
3. A Claude telemetry block was copied into Codex's global child-process environment. It does not configure Codex telemetry; it can unexpectedly enable detailed telemetry in Claude or other OpenTelemetry-aware processes launched by Codex.
4. Several imported instruction, tool, command, and agent files are either in unsupported discovery locations, refer to missing components, have invalid metadata/tool permissions, or still assume WSL.
5. The installation is over-broad: 32 Codex plugins, 22 enabled Claude plugin settings, 43 Codex user-skill files, and 21 Claude personal-skill files create duplication and context/discovery pressure. One shared skill has malformed strict YAML frontmatter, and one additional Claude skill directory contains tests but no `SKILL.md`.

I did not directly edit the imported configuration. One validation command went through Codex's approval workflow, which automatically appended the narrow `codex --version` allow rule to `C:\Users\aboog\.codex\rules\default.rules`. Apart from that approval-state change, this report is the only file created.

## App and plugin diagnostics not proven to be merge defects

These observations deserve follow-up but should not be blamed on `agent-config-merge-skill` without stronger causal evidence:

- Codex logs contain three `legacy_notify` failures with Windows error 206 on August 7, 8, and 12. The configured notify executable is app-generated, versioned, and currently exists. This looks more like a Windows command-length/runtime integration problem than a copied WSL path.
- Codex logs warn about unknown feature key `thread_tools`, but no such key appears in the visible user `config.toml`. It may come from stale app state, a managed layer, or an older migration.
- Repeated missing/invalid authentication for GitHub Copilot, Sentry, and Stripe is consistent with enabled plugins whose connections were never completed. OpenAI's import guide explicitly warns that imported plugins and MCP connections can require manual setup or reauthorization.
- A standalone bundled `codex mcp list` did not expose the app-provided `node_repl`, although the desktop session is actively using that runtime. This is a client/app-layer discrepancy, not proof that the live desktop MCP is broken.
- Two Claude executables are installed (`2.1.201` first on `PATH`, plus an older WinGet link at `2.1.116`). The current resolution is healthy, but a future `PATH` reorder could silently run the older client.

## What is healthy

- `config.toml`, Codex `hooks.json`, Claude `settings.json`, and Claude `mcp.json` all parse successfully.
- The Windows paths used by Codex `notify`, `node_repl`, its Node runtime/module directory, `CODEX_HOME`, `CODEX_CLI_PATH`, marketplace roots, and both collector hook command components exist.
- The current Codex model cache recognizes `gpt-5.6-sol`, `max` reasoning, and the `priority` service tier used by `config.toml`; those are not merge errors even though generic web documentation can lag the bundled runtime.
- All 43 top-level Codex personal skill directories contain a `SKILL.md` with declared `name` and `description` fields; no duplicate declared names were found inside that root. The strict-YAML exception is called out above rather than hidden in this baseline.
- The Codex rule syntax is valid and narrowly scoped. No broad wildcard allow rule was found.
- The imported collector SessionStart hook is explicitly disabled rather than being silently trusted.
- A focused literal scan found no obvious embedded API keys, bearer tokens, or private-key blocks in the inspected portable config, instruction, command, agent, and skill files. Secret-bearing stores were deliberately excluded and no secret values are included in this report.

## Recommended operating model

Do not use “copy everything” as the steady-state synchronization policy. The approved design in `D:\Documents\Code\GitHub\.claude_code\Docs\plans\2026-08-08-wsl-authoritative-agent-config-sync-design.md` is the right model and this audit reinforces it:

1. Treat WSL as the authority for **portable user intent**, not for machine state.
2. Keep `.claude_code` as the sanitized, version-controlled comparison baseline.
3. Treat Windows as a derived target with a protected overlay for Desktop settings, executable paths, shell choice, hooks, project trust, plugin runtime state, and MCP authentication.
4. Use deterministic allowlist extraction and a report-only drift job. Apply changes only after human review, with a timestamped backup and rollback path.
5. Reconcile plugins through each product's native manager. Never copy plugin caches or downloaded runtime code.
6. Exclude credentials, OAuth/keychain state, histories, sessions, memories, databases, caches, logs, telemetry state, machine IDs, and trust/approval state by default.

That model preserves cross-agent consistency without pretending WSL and native Windows have interchangeable paths, discovery rules, transports, or trust boundaries.

## Recommended remediation order

1. **Repair Claude model selection:** use `/model fable`, then check `/status` and `/doctor`.
2. **Recreate MCP servers natively:** decide which of the three are still needed, add them with explicit commands/transports, reauthenticate, and validate connections. Do not copy credentials from WSL.
3. **Decide telemetry policy:** identify what listens on `localhost:3000`, where it forwards data, and whether detailed tool arguments are acceptable; then relocate or remove the Claude OTel block from Codex.
4. **Restore discovery semantics:** move/import the package-age instruction, package the safe reader as a skill helper, and correct the Codex graphify name/trigger.
5. **Repair or prune workflows:** fix the reviewer agent's tool contract, move the documentation file out of `agents/`, fix the missing `sync-claude-config` skill, make wanted commands cross-platform, and rebuild only the subagents actually used.
6. **Curate extensions:** repair the `gpt-image-2` YAML, remove the incomplete `version-manager` directory, remove the stale `ralph-wiggum` entry, resolve authentication only for plugins kept enabled, choose authoritative copies for duplicate skills, and prune unused plugins.
7. **Review hooks and rules:** explicitly enable or remove the collector hook; move project-specific rules out of the user-global layer.
8. **Run interactive validation:** Codex `/hooks`, `/mcp`, and skills view; Claude `/doctor`, `/status`, `/hooks`, `/mcp`, `/permissions`, `/skills`, `/agents`, and `/model`.

## Scope and validation limits

- Imported settings, hooks, plugin declarations, MCP definitions, instructions, agents, commands, and skills were inspected read-only. The only global-state mutation was the narrow `codex --version` approval rule automatically recorded by Codex during validation; no other global values were changed.
- Secret-bearing state such as `auth.json`, `.credentials.json`, OAuth values, and raw MCP authentication material was intentionally not reported.
- This was a native Windows audit. WSL enumeration was denied in the current sandbox, so the source tree was not re-read; the report identifies Windows defects and drift indicators but does not claim a complete WSL-to-Windows diff.
- MCP servers were not started and external authentication was not attempted. One sandboxed `claude mcp list` health check timed out; the configuration-state conclusions come from supported file locations and non-secret CLI configuration checks.
- Plugin failures and Codex log messages were classified by evidence; app-generated runtime warnings were not automatically attributed to the merge.
- The official docs describe import as additive: it leaves the existing setup unchanged. Duplication and stale pre-existing entries therefore require human curation after import. [OpenAI import documentation](https://learn.chatgpt.com/docs/import)
