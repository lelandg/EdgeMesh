# Security floors for transitive dependencies. This file installs nothing on its
# own: it is a pip CONSTRAINTS file, included from each requirements file with
#     -c requirements-security.txt
# so a fresh install resolves to patched versions instead of the oldest version
# that satisfies a loose `>=` floor.
#
# Why this exists: osv-scanner (and pip, given `pkg>=X`) resolves to the MINIMUM
# satisfying version. A repo declaring `streamlit>=1.22.0` and nothing else
# resolved a transitive `pillow 9.5.0` and reported 84 advisories. Raising the
# floor is the fix; the advisory count is the acceptance test.
#
# Floors are the LOWEST release that clears every advisory affecting the version
# actually resolved -- not the latest release -- per the house rule that
# remediation must not smuggle in a feature jump.
#
# Pattern and precedent: ImageAI/requirements-security.txt, which has been in
# production use and keeps that repo at zero open Dependabot alerts.
#
# A constraints file CANNOT relax an exact pin. If a repo declares `pillow==X`,
# edit that pin directly; adding a conflicting constraint makes pip fail.
