Make your first mesh

  1. Open an image.Use Open Image, or begin with the example from Setup. Your source stays available for comparison.
  2. Choose the subject.Open the mask editor. Add and remove foreground with brushes, or use SAM2 points and a box. Accept the selection to apply it to Depth Mesh.
  3. Choose a mesh route.Depth Mesh uses an estimated depth surface. Contour Mesh uses image edges and does not use a learned model; its result has different geometry and mask semantics.
  4. Generate and inspect.Inspect the embedded viewer, fit the mesh, switch standard views, and compare surface and wireframe display. Adjust depth amount and regenerate if needed.
  5. Save the result.Check the displayed project folder and autosave status. Save a project copy for a separate destination; export a mesh when you need an OBJ or STL outside the project.

A depth mesh from one photograph is a relief. A full object reconstructed from several photographs, or an AI-generated guess at its hidden surfaces, is a separate workflow.

Know where your work is saved

Visible project folder

The app shows the current project folder and autosave state. A project folder is created automatically when needed; inspect the shown location rather than guessing where files went.

Change or save a copy

Use the folder control to change where the project is saved. Save Copy writes a separate project copy to a destination you choose. Keep the original when comparing variants.

Save project versus image

Project saving retains the workflow state and its associated data. Save Image writes an image file. Mesh export is a separate operation; choose it when another application needs the geometry.

Plain project data

Project metadata is readable JSON. Provider credentials are kept out of project files. Readable metadata and local integrity checks serve different purposes; project files are not encrypted by those checks.

Check the autosave status if a destination is unavailable or a save fails. A chosen location is not evidence that its latest write succeeded.

One processed view, with an editable selection

The processed-image preview and accepted mask share a view. Use the overlay or mask display to inspect the selection alongside the processed result. There is no separate Processed page to manage.

Make space for the image

Resize the splitters between preview areas. Move, resize or detach the parameter dock; use View to restore a hidden panel or reset the layout.

Refine the mask

Adjust display mode and opacity, then open the editor for points, a box or manual brush corrections. Accept applies the edit; Cancel preserves the previously accepted selection.

History

Review saved states and processing choices, compare settings and restore the state you want to continue from. Regenerate when restored settings require a new mesh.

Setup and Assistant

Setup holds model and local configuration controls. Assistant holds optional provider connections. Basic image, mask, contour and preview work does not require an AI account.

Connect an AI provider when you choose

Configure optional connections in Assistant. Authentication belongs to the provider connection on this computer; project copies do not carry credentials.

Codex

Connect through the supported OAuth login or an API key. Provider authentication and model availability are separate from the local mask and mesh workflow.

Claude

Use the supported OAuth login or an API key. Keep account and connection details in local settings, outside project metadata.

Antigravity

Modern Antigravity supports the protected embedded OAuth connection. The older installed CLI can still own account login, but requires an upgrade for the protected embedded streaming route. An optional API-key connection uses the supported SDK worker and does not require that external CLI.

Understand what is connected

A connected coding assistant is not automatically a separate image- or video-generation API entitlement. Use the capabilities the configured provider actually exposes.

This reference describes the connection choices. It does not report a successful live login, paid request or cloud-generation test.

Read model terms alongside the accepted mesh

Noncommercial, research-only and custom-license labels follow the model provenance of the accepted mesh. A later change in the model picker does not relabel an already accepted result.

Terms are model-specific

A badge summarizes the relevant upstream terms; it does not grant permission. Research-only and noncommercial are not interchangeable. Depth Pro's terms exclude product development; do not interpret an NC label as permission for any other use.

Contour has no learned model

The contour route uses image processing rather than a learned model. Its provenance should say so instead of borrowing a license label from a previously selected depth model.

Local tamper evidence

A source hash and HMAC record help detect changed provenance. On Windows, the local signing key is protected with DPAPI. The project JSON remains readable.

Portable means verifiable only where possible

A project signed with a different computer's key is unverified locally. These checks are tamper evidence, not DRM, proof of licensing permission or encryption of the project.

Depth amount and resolution

The flattening problem came from measuring X/Y in image pixels while leaving Z at a fixed size. Depth scaling now follows the image proportion: at Depth 1, the available depth range is half the longer image side. Changing processing resolution therefore does not, by itself, flatten the same relative depth shape.

This scale is a relief setting, not a measured physical dimension. Actual cached DA1 and DA2 runs produced varied depth and watertight meshes with consistent proportions. See the measured comparison for revisions, settings and timings. These small CPU runs used an illustration; they do not establish model accuracy or a quality ranking.

Depth Anything 3 uses an optional local runtime

Follow Depth Anything 3 setup, then select Small, Base, Mono-Large or Metric-Large in the depth model picker. These checkpoints use Apache 2.0 weights. Inference runs locally in a separate runtime and returns depth to the existing preview and accept workflow. The mesh uses normalized relief scale, including for Metric-Large. Multiview reconstruction is not exposed by this integration. See Model options for other checkpoints and their terms.
